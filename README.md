# sbswe · Slightly Bigger SWE Agent

sbswe is a small coding agent for the terminal, built on [mini-swe-agent](https://github.com/SWE-agent/mini-swe-agent). It works on local repositories and asks you to approve tool actions. Long conversations are compacted, and large command outputs are saved so you can read them later.

[Getting started](#getting-started) · [Commands](#commands) · [Providers](#providers-and-models) · [Security](SECURITY.md) · [Releases](https://github.com/R0sso-Corsa/Slightly-Bigger-SWE-Agent/releases)

> sbswe is experimental and is not sandboxed. Commands generated by the model run with your account's access. Use a disposable workspace and credentials with only the permissions you need. Read [SECURITY.md](SECURITY.md) before running tasks.

## Features

| Feature | What it does |
| --- | --- |
| Provider setup | Add or switch saved endpoints in the CLI. API key input is hidden. |
| Model picker | Search your provider's live catalog and save a default before starting a chat. |
| History compaction | Condense older messages when the conversation exceeds its character budget. |
| Output spooling | Save large tool output to `.sbswe_spool/`. The preview shows the beginning, end and path to the full output. |
| Working-directory tracking | Shell commands and relative file-tool paths follow the shell's current directory. |
| File tools | Read, write, list, find and search files, or use the shell directly. |
| Structured submission | Use the `submit` tool to finish a task. Completion does not depend only on text markers. |
| Approval and guardrails | Ask before interactive actions. A small deny list blocks some dangerous command patterns, but it does not provide isolation. |

## Getting started

You need Python 3.10+ and a POSIX shell. The project is tested locally on macOS and in Linux CI. Windows has not been verified for release.

```bash
git clone https://github.com/R0sso-Corsa/Slightly-Bigger-SWE-Agent.git sbswe
cd sbswe
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
sbswe --configure
```

You can also install the wheel from [GitHub Releases](https://github.com/R0sso-Corsa/Slightly-Bigger-SWE-Agent/releases) in a virtual environment:

```bash
python -m pip install ./sbswe-0.2.0-py3-none-any.whl
sbswe --configure
```

The wizard asks for a `provider/model` identifier, an optional base URL and an API key. It tries to name the endpoint automatically. If it cannot identify a custom endpoint, it asks you for a name. To choose your default model:

```bash
sbswe --models
```

Start an interactive conversation:

```bash
sbswe --cwd /path/to/your/repo
```

You can enter a task across several lines. Press Esc, then Enter to submit it, or Ctrl+C to cancel. Tool actions ask for approval by default. Follow-up tasks keep the conversation context.

### Run a single task

```bash
sbswe --task "Find and fix the failing test" \
  --cwd /path/to/your/repo \
  --step-limit 20
```

When running with redirected input or in automation, you must pass `--yolo`. This skips approvals:

```bash
sbswe --task "Run the test suite and report failures" \
  --cwd /path/to/disposable-checkout \
  --step-limit 10 \
  --yolo
```

## Commands

| Command / option | Purpose |
| --- | --- |
| `sbswe` | Start an interactive task prompt. |
| `sbswe --configure` | Add, edit or activate a saved endpoint. |
| `sbswe --models` | Select an endpoint, search its models, and save a default. |
| `sbswe --reauth` | Replace the active endpoint's API key using hidden input. |
| `-m provider/model` | Override the model for one run. |
| `-c file.yaml` | Override user defaults with a YAML config. |
| `--cwd PATH` | Set the task's working directory. |
| `--tools bash,submit` | Choose enabled tools; these two are the default. |
| `--step-limit N` | Limit model calls per task/turn. |
| `--cost-limit AMOUNT` | Limit reported model costs where pricing is available. |
| `-o trajectory.json` | Save the task trajectory; treat it as sensitive. |
| `--help` | Show all options. |

`python -m sbswe` is equivalent to the `sbswe` command.

To enable the file tools:

```bash
sbswe --tools bash,read_file,write_file,list_dir,find_files,grep,submit
```

## Providers and models

sbswe sends requests through LiteLLM. Include the provider route in the model identifier: an OpenRouter catalog ID becomes `openrouter/<catalog-model-id>`. The publisher's name alone may not identify the provider. Running `--configure` saves settings without validating credentials or making a completion request.

### Pick a model without starting chat

```bash
sbswe --models
```

1. Choose a saved endpoint by number.
2. Enter a search term, or leave it blank to list all returned models.
3. Select a model by number.

Your selection becomes the default for the next chat. The picker can fetch model lists from OpenRouter, OpenAI, Anthropic, Groq, DeepSeek and Mistral, plus custom endpoints that return the OpenAI-compatible `/models` format. If it cannot fetch a list, you can enter the model manually.

A listed model may still be unavailable to your account or region. The `chatgpt/` route can use existing ChatGPT OAuth credentials, but the wizard cannot start a browser login or discover OAuth model catalogs. Use `--reauth` to replace an API key; it does not renew an OAuth login.

### Settings and credentials

| Location | Contents |
| --- | --- |
| `~/.config/sbswe/config.yaml` | User defaults, named endpoints, and the selected model. |
| Checkout `.env` | Keys for an editable source install; gitignored. |
| `~/.config/sbswe/.env` | Keys for an installed wheel. |
| `.env.example` | Placeholder credential variables you can copy into your local file. This template is safe to commit. |

`XDG_CONFIG_HOME` overrides the `~/.config` base directory. The wizard gives key files owner-only permissions (`0600`) and saves references such as `${SBSWE_ENDPOINT_..._API_KEY}` in YAML. The entered key stays in the key file.

If you edit the YAML yourself, you can reference environment variables with `${VAR}` or `$VAR`:

```yaml
model:
  model_name: openrouter/<catalog-model-id>
  api_key: ${OPENROUTER_API_KEY}
```

Keep the key itself in `.env`:

```bash
cp -n .env.example .env
# Edit .env locally; never commit it.
```

Shell variables take precedence over values in the editable checkout `.env`, which take precedence over the user `.env`. The model name is chosen in this order:

```text
CLI -m > SBSWE_MODEL > explicit -c config > user config > built-in fallback
```

An endpoint's saved key and base URL override generic `OPENAI_*` defaults. CLI flags override those saved settings. When you switch providers, sbswe prevents the previous provider's key from being reused silently. Restart the chat after changing settings.

### Custom endpoints

Use `--configure` to save an endpoint. For an endpoint already configured with
the `openai/` route, you can override its model and URL for a run:

```bash
sbswe -m 'openai/<model-id>' --base-url http://localhost:8080/v1
```

Use HTTPS for remote services. You can use HTTP with a local server, but it sends credentials without encryption.

## Safety and limits

- Shell and file tools have your account's access. Child commands inherit environment variables. There is no sandbox.
- Interactive actions require approval unless you set `--yolo`. Non-TTY task execution requires explicit `--yolo`.
- Unknown pricing can report a cost of zero, so the cost limit may not stop spending. Set spending limits with your provider and use a finite step limit.
- Terminal output, spooled files and saved trajectories are not automatically redacted. Check them for sensitive information before publishing.
- The deny list catches specific command patterns. It cannot protect you from arbitrary malicious instructions.
- MCP/ACP integration, richer cancellation and dedicated prompt-cache controls are still deferred.

Read [SECURITY.md](SECURITY.md) for the security limits. [RELEASE.md](RELEASE.md) records the release checks and what they cover.

## Development

```bash
python -m pip install -e '.[dev]'
python -m unittest discover -v
basedpyright -p .
python -m build
python -m twine check dist/*.whl dist/*.tar.gz
```

CI runs the tests and typechecker on Python 3.10 and 3.13. It also builds the packages, checks their metadata and tests a fresh wheel installation.

```text
sbswe/
  agent.py          Agent loop, approvals and compaction
  cli.py            Interactive chat and CLI options
  configuration.py  Endpoint setup, key rotation and model picker
  env.py            Shell execution, cwd tracking and output spooling
  model.py          LiteLLM adapter and tool schemas
  tools.py          Built-in file tools
config/             Example YAML templates
```
